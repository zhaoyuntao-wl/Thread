# 会话管理系统设计文档 v1（Session Memory System）

> 日期：2026-08-07 ｜ 状态：**v1 基线**——需求与架构已确认，MVP 已实现（2026-08-07 修订：底座定位修正 + 开源计划；2026-08-12 修订：底座确认为 Qoder CLI，Codewhale 降为第二候选适配器；2026-08-13 修订：按版本拆分——二期规划 / 开放问题 / 作用域设计移至 [v2 文档](../v2/session-memory-system-design.md)）
> 定位：编码 Agent 的**上下文保真**记忆层——独立开源项目 **Thread**（Session memory with lineage for coding agents），底座无关

---

## 1. 背景与动机

- 痛点：长任务连续对话中，主流压缩机制（Claude Code auto-compact、Codex compact 等）导致**内容遗漏、注意力偏移、胡言乱语**。
- 结论：主流"压缩派"（信息全在场但不可逆降质）vs 本方案"检索派"（信息无损存储、按需取用）。
- 行业验证：Claude Code 压缩翻车是公开事实；agentmemory / claude-mem 等记忆层项目快速增长，但**无人做透"编码会话决策链保真"**——这是差异化空间。

## 2. 定位

- **编码代理**（编码优先，通用场景用 MCP 补齐）。
- **核心差异化**：长任务连续对话保真——决策不丢、目标不漂移、不重复提问。
- **第二支柱**：模型调度——v1 静态角色分工，v2 动态路由。

## 3. 总体架构

```
┌─────────────────────────────┐        ┌──────────────────────────────┐
│  底座（Qoder CLI，可互换）   │        │  会话管理系统 SMS（独立进程）   │
│                             │  MCP   │                              │
│  主模型（唯一同步模型）◄──────┼────────┼──► 查询服务（图/BM25/向量）    │
│  工具（query_session_memory）│ hooks  │  事件流水（无损存储）          │
│  对话流导出（用户/回复/工具）──┼───────┼──► 结构化表（目标/决策清单）    │
│  每轮上下文注入（目标+状态卡） │        │  血缘图（实体+事件双层）       │
└─────────────────────────────┘        │  旁路模型（异步写时/监听）    │
                                       └──────────────────────────────┘
```

- **薄接入**：SMS 为独立进程，通过 MCP 工具 + hooks 接入底座。
- **底座约束（弱，可互换）**：
  1. MCP 客户端（暴露 `query_session_memory`）
  2. hook 事件覆盖：用户消息 / 模型回复 / 工具调用 三类事件可捕获
  3. 每轮上下文注入：把"目标 + 情节状态"塞进每轮上下文
- **主路径原则**：主路径上唯一同步模型是主模型；其余模型全部旁路（异步写时 / 输出流监听 / 兜底）。

## 4. 存储层

- **事件流水（无损）**：用户消息 / Agent 回复 / 工具调用原样落库，带时间戳与元数据。
- **情节（Episode）分组**：规则判定（工具类型切换、用户新指令等）；情节有独立摘要 + 状态。
- **结构化表**：
  - 目标表（顶层意图）
  - 决策清单（状态机：提议 → 确认 → 生效 → 被取代 → 撤销）
  - 反馈/偏好表（用户纠正与偏好，如"以后不要这样做"——与任务决策互补，跨会话复用；双作用域 global/project 见 [v2 设计](../v2/session-memory-system-design.md)）
- **写时即建索引**：事件写入时同步完成——确定性实体（路径/函数/命令/URL/数字）程序化抽取；语义元数据由旁路模型异步抽取（可失败可重试，**绝不阻塞对话**）。

> MVP 实现注记：决策状态机的确认与生效合并为一步（用户认可即生效），状态集为 提议/生效/被取代/撤销；显式"确认"态留待二期（如需两步确认）。

## 5. 血缘层（双层）

- **实体关系图**：管"找什么"——实体（文件/函数/决策/任务/模型/…）+ 类型化关系边。
- **事件流水链**：管"凭什么"——时序 / 因果 / 父子关系，可遍历。
- **边携带证据**：每条边含（类型 + 源事件 + 置信度 + 时间戳）；查询返回**证据路径**而非裸节点，每次跳转有据可依。
- **预留接口**：链接 code-review-graph（代码知识图谱），实现"会话决策 ↔ 代码实体"贯通——二期。

## 6. 检索与组装

- **常驻上下文最小集**：目标 + 当前情节状态 + 最近对话尾巴（不随对话增长）——**关键路径永不依赖检索**。
- **静态知识按需加载**（吸收 Qoder rules 模式）：`AGENTS.md` 层级化静态管理 + 规则支持 `glob`（指定文件生效）/ `model_decision`（模型判断生效）触发——只在相关时注入，不进常驻最小集。
- **主动查询协议**：模型需要更多信息时调用 `query_session_memory()`（见附录 API 草案），带 token 预算。
- **降级链**：图查询 → BM25 全文检索 → 情节摘要兜底 → **未找到契约**。
- **未找到契约**：无结果时 API 强制携带 `not-found` 标记，模型必须诚实声明"记忆中没找到 / 需要用户补充"，**绝不允许编造**。

> MVP 实现注记：情节摘要为确定性实现——情节闭合时拼接事件正文截断（4000 字符）；摘要模型正式化后替换。

### 按需检索的保证（四重兜底）

1. **关键路径不依赖检索**：必须有的信息（目标/决策/情节状态）常驻状态卡；检索只服务辅助信息（历史细节、旧工具结果）。
2. **确定性触发**：程序检测到模型即将修改某文件 / 调用某工具时，主动预检索该文件的决策与引用（不靠模型自觉）。
3. **模型主动查询**：query 工具 + 系统提示词契约。
4. **失败可见可度量**：未找到契约使失败可见；漏召回日志使失败可迭代。

> 边界声明：完美召回无法保证（检索范式固有边界），但保证"关键信息不依赖它 + 失败可见 + 失败可度量"。

### 多次检索结果的关联（三机制）

1. **图锚定扩展**：后续查询可锚定在先前结果上（`anchor`，沿血缘图边链式遍历）——多次查询是证据路径上的遍历，关联由图结构保证，不靠模型脑补。
2. **回合内检索工作集**：同一回合的多次查询共享工作集，系统去重、按情节归组、合并为一份连贯 memory brief 再交还模型（碎片不逐个丢给模型）。
3. **一致性标记**：决策带状态机（生效/被取代/撤销），返回过期决策时携带撤销链标记——冲突结果是被标记的冲突，非静默矛盾。

**溯源约束**：模型回合末的回答必须标注所用片段，是否串联多次检索结果可审计。

## 7. 模型分工

| 角色 | 触发点 | 约束 |
|------|--------|------|
| 主模型 | 用户消息、工具结果返回 | 主路径唯一同步模型 |
| 语义抽取模型 | 事件写入时（异步） | 可失败可重试，不阻塞对话 |
| 轻确认模型 | 旁路监听主模型输出流 | 只产出"状态是否变化"判断 |
| 摘要模型 | 降级链末级、情节归档 | 兜底用 |

- **旁路只看局部**：轻确认模型输入 = 当前回合（用户消息 + 主模型回复）+ 状态卡（目标 + 决策清单，几百 token）——**不做全局理解**，避免"左脚踩右脚"。
- **确定性预过滤**：程序先筛（信号词、工具调用类型、用户明确认可），筛中才轮到旁路模型。
- **决策显式写入**：旁路发现状态变化 → 主模型在对话内自然语言轻确认（"我记下了方案 A"）→ 用户认可即写入决策清单。漏判不致命：事件流水无损，决策行只是加速器。

### 旁路本地化与解析顺序链

- **旁路任务全部可本地化**（简单任务，不需要大模型）：
  - 轻确认 = 文本分类（本地小分类器 0.1-0.4B，或规则 + embedding 相似度，毫秒级）
  - 语义抽取 = 结构化生成（本地小 LLM 3B 档，Q4 量化约 2GB 内存，异步批量执行）
  - 重排 = bge-reranker（100-400M 参数，本地部署标准做法）
  - embedding = bge-m3 本地
  - 摘要 = 本地小 LLM 或主模型兜底（低频）
- **执行器解析顺序链**：① 本地模型（默认：隐私、零额外成本）→ ② 同一 provider 的便宜档（如 deepseek-chat）→ ③ 主模型（最后兜底，输入极小、代价可控）。
- **无本地模型自动降级**：只做确定性抽取（路径/实体），语义边延后（二期）——旁路是增强层，降级不破坏核心。
- **隐私卖点**：记忆处理（分类/抽取/重排/embedding）全程本地，对话内容仅在主模型调用时出网。
- **代价**：安装包变大（模型文件）——用"模型按需下载"缓解。

## 8. 用户交互

- 用户始终像正常人聊天，**不接触记忆系统**。
- 关键决策时对话内多一句"我记下了…"，用户"嗯"即确认；说错当场纠正。
- 可选项（预留）：记忆面板（查看/修正历史），默认关闭。

## 9. 评估体系

- **回归集**：5~10 个长任务场景（2-3 小时连续开发），程序化检查关键事实保留率（决策还记得吗 / 目标漂移吗 / 重复提问吗）+ 人工抽检；同一任务**三向对比：Claude Code + Qoder CLI vs Thread**（Qoder 官方文档承认 compact 有损、自动记忆可能过期，证据背书天然）。
- **备注**：Hermes Agent（Rust 系最大开源 Agent，17 万星，上下文管理仍有损压缩）列为**后续对比候选**——初期不纳入，待 v1 验证后如需强化开源叙事证据再扩为四向；亦不引入其适配器（狗粮底座已定 Qoder CLI）。
- **线上度量**：漏召回率、重复提问率、用户纠正率（轻确认被否定的比例）。
- **迭代闭环**：漏召回日志（模型问了已答问题 / 重复操作等模式）反向驱动组装策略调优。

## 10. 底座与接入

- **Qoder CLI = 狗粮底座 + 第一参考适配器**（非二开对象）。
- 理由：为实际日常使用底座，狗粮数据真实；三弱能力已实证原生支持——hook 事件（UserPromptSubmit / PreToolUse / PostToolUse / Stop，JSON 载荷）、上下文注入（hook stdout `systemMessage` / SDK `additionalContext`）、MCP 客户端（stdio）。
- **Codewhale（Hmbown/CodeWhale，Rust / MIT，原 DeepSeek CLI 改名项目）= 第二参考适配器（候选）**：hook 能力未验证，待冒烟调研后定级；缺项记差距 + 替代路径，不阻塞核心。
- 注：验证叙事**不依赖**任何底座"上下文差"的主观判断——验收标准是绝对标准（回归集对比 Claude Code 的公开 auto-compact 问题），非相对优劣。
- **薄接入**：SMS 独立进程，通过 MCP 工具 + hooks 接入；底座只依赖三个弱能力（MCP 客户端 / hook 事件覆盖 / 每轮上下文注入），可互换。
- 日常工具可随时切换，不影响 SMS 核心。

## 11. MVP 范围

1. 事件流水（无损落库 + 情节分组规则）
2. 目标 / 决策结构化表 + 状态机
3. 轻确认旁路（局部输入：回合 + 状态卡）
4. 血缘图**确定性边**（工具调用 → 结果 → 决策引用 → 文件路径；语义边二期）
5. BM25 检索 + `query_session_memory` 工具（MCP）
6. 未找到契约
7. 5~10 场景回归集（三向：Claude Code + Qoder CLI vs Thread）

**MVP 成功标准**：同样的长任务，决策不丢、目标不漂移、不重复提问。

### 开发里程碑（垂直切片）

1. **底座冒烟验证**（半天）：三弱能力最小可用验证——hooks 三类事件导出（格式可解析）/ MCP 工具注入可调用 / 上下文注入有钩子或等效途径；不满足项**记差距 + 替代路径**（wrapper / 状态卡工具自读），不阻塞开工。**产出：适配器能力清单**（原生支持 / 需 workaround），作为适配器设计输入。
2. **最小端到端链路**：hooks 事件流 → 落库 → query 工具（MCP）→ 在 Qoder CLI 里真实查询一次——优先验证"底座适配器 + 事件流 + query 工具"这条最大风险链。
3. **横向扩展**：结构化表（目标/决策/反馈）→ 轻确认旁路 → 血缘确定性边 → 检索降级链 / 未找到契约 → 回归集三向。
4. **熟人内测**：2~3 位朋友/同事，收集外部真实数据。

> 说明：**不需要底座源码**——已安装二进制 + 官方文档即可开发；源码仅在文档未覆盖 hooks 细节时作参考阅读（读，不 fork）。

## 12. 开源计划（Thread）

- **形态**：独立项目开源（不做任何项目的分支）——通用记忆层，底座无关。
- **名称**：Thread；副标题 *Session memory with lineage for coding agents*。
- **许可证**：Apache-2.0（全新代码，无派生负担，企业友好）。
- **技术栈**：TypeScript/Node；pnpm monorepo（`packages/core` + `packages/adapters/qoder-cli` + `packages/adapters/codewhale`（候选）+ `packages/evals` + `docs`），changesets 统一版本。
- **适配器**：Qoder CLI 参考适配器内置本仓库（同版本同 CI，保证开箱即跑）；Codewhale 侧只放文档推荐位（候选，能力调研后定）。
- **狗粮**：日常开发与验证使用 Qoder CLI + SMS。

### 发布节奏（三阶段）

1. **私有开发**：MVP（见第 11 节）+ 回归集（5~10 长任务场景，对比 Claude Code）。
2. **熟人内测**：2~3 位朋友/同事，收集外部真实数据（漏召回率、纠正率）——他证比自证硬。
3. **公开**：验证通过后 GitHub public + 发布文章（国内社区为主）；**不运营社区**，靠 issue 自然运转。

### 开源标准建设（从第一行代码起）

- Apache-2.0 LICENSE、CI（typecheck / lint / test / evals 冒烟）、README 骨架、issue 模板、CONTRIBUTING。

## 13. 成本模型（tokens / 缓存 / 调用次数）

### 输入 tokens 变化

- **短对话**：略增——状态卡几百 token 的固定开销。
- **长对话**：显著下降——上下文 **O(1) 有界**；主流 O(n) 累加的历史改为按需碎片拉回。
- 本质：用"按需检索的小成本"换"历史全量重读的大成本"。

> MVP 状态注记：O(1) 有界是**目标架构**；当前 MVP 只做加法（注入状态卡 + 提供检索），底座仍自行重发全量历史——ctx 下降依赖"底座侧上下文裁剪接入点"（见 [v2 文档](../v2/session-memory-system-design.md)·开放问题），未接入前 MVP 实际效果为：ctx 略增 + 关键信息有保底可恢复。

### 缓存命中率

- **比主流更高更稳**：无 compact → 无周期性全破；前缀稳定可预测。
- **组装硬规则：上下文按变化频率从前往后排序**——恒定（系统指令/契约）→ 低频（状态卡，追加式更新）→ 高频（尾巴/工具结果/检索碎片）。
- 状态卡**追加式**更新（新决策只 append 末尾），前缀几乎永远稳定。
- 每轮实际新写入仅：尾巴滑入段 + 本轮工具结果 + 检索碎片。

### 调用次数（澄清：检索不是模型调用）

- `query_session_memory` 是**程序化检索**（BM25 / 图遍历 / 向量），零 LLM 开销。
- 模型调用增量仅两类：
  1. **旁路模型**：确定性预过滤后触发（约 10-30% 回合）；异步不阻塞；可批量 / 空闲期执行；便宜模型 + 局部输入。
  2. **主循环 query 工具轮次**：每次 = 2 次推断（发起 + 消化），受预算控制。
- 对比主流：**次数少但单次贵**（O(n) prefill 全量重读）vs 我们**次数多但单次便宜**（O(1) + 高缓存命中）。
- 正确度量：**总成本 = Σ(次数 × 单次 tokens × 单价)**，不是次数。

### 延迟

- query：一次本地检索往返（毫秒级）。
- 长对话省去 O(n) prefill 时间——**长对话反而更快**。
- 旁路全异步，不阻塞主路径。

### 新增成本项

- 旁路模型调用（便宜模型、小输入、可用缓存）。
- embedding（本地模型免费或 API 极便宜）。
- 存储：SQLite + 索引（一次性磁盘开销）。

### 结论

- 长对话：输入成本大降 + 缓存命中率上升 + 无 compact 击穿，**净省明显**。
- 短对话：略增，可接受。
- 一句话：**用"多一点便宜调用"换"少一大截昂贵重读"**——次数是表象，总成本才是实质。

## 附录：`query_session_memory` API 草案（v0）

```
query_session_memory(query: string, opts?: {
  token_budget?: number,        // 返回结果总预算（token），默认 4000
  scope?: "session" | "episode" | "graph" | "all",  // 默认 all（走降级链）
  must?: string[],              // 必须命中的类别：goal | decision | entity
  anchor?: string,              // 锚定扩展：从该 segment 沿血缘图边链式遍历
})
→ {
  status: "found" | "degraded" | "not-found",
  results: [{
    segment_id: string,         // 锚定到事件流水
    kind: "goal" | "decision" | "entity" | "event" | "summary",
    text: string,
    score: number,
    evidence_path: [{
      node: string, edge_type: string,
      source_event: string, ts: string,
    }],                          // 每条结果携带证据路径
  }],
  note?: string,                 // not-found 时强制携带：未找到说明
}
```

**契约**：`not-found` 时模型必须回应"未找到"并主动向用户追问，不得编造。
