批次按依赖排序：**A（前置调研，已完成）→ B（记忆层能力，主体已落地）→ C（智能增强，未开始）**，里程碑 + 验收标准粒度，不排具体日期。

### 批 A：前置调研（已完成）

- 底座侧上下文裁剪能力调研 → 结论：PreCompact/PostCompact hooks 可用，底座可控路径成立
- 本地旁路模型选型（桌面调研）→ 结论：全部本地化（轻确认分类器 / 语义抽取小 LLM / embedding / reranker，详见本地设计文档）

### 批 B：记忆层能力（主体已落地）

0. **上下文裁剪接入（O(1)）**：挂 PreCompact/PostCompact hook——PreCompact 时状态卡落库防丢，PostCompact 后重新注入状态卡，细节靠检索拉回。**实机验证**：`compact_checkpoint` 事件入流水（body=摘要全文）——摘要即压缩边界血缘标记，可检索；状态卡回归由每轮注入保证（压缩后下一条用户消息即恢复）。`scripts/eval-ctx.mjs`（每轮上下文曲线重建）+ `scripts/eval-compare.mjs`（同任务前后对比）已建。
1. **作用域与命名空间**：用户级结构化库 + 按项目键分事件库、项目键推导、查询合并（project+global）、状态卡合并显示、非当前项目硬过滤 —— **已落地**
2. **跨会话自动继承（轻量版）**：新会话开场注入上一项目会话的 active 决策 / 全局反馈（最近 N 条）—— **已落地**
3. **串库迁移**：旧单库 → 新结构（用户级 + 项目库）数据无损迁移，project_key 回填 —— **已落地**
4. **线上度量埋点**：漏召回率 / 重复提问率 / 纠正率轻量日志 + 检索提醒治理度量 —— **已落地**
5. **压缩派弱点低成本补强包**：
   - 反馈拦截：反馈表命中教训 → deny（教训从提示升级为强制）。确定性匹配：反馈行提取"禁用指令"目标工具名 → 与待执行工具名 case-insensitive 匹配 → 命中即拒绝，拒绝原因 = 教训原文。接缝：dsh = `ctx.tools.guard()`；Qoder = `PreToolUse` 同步 hook。**恢复通道**：`deleteFeedback` + `/feedback-del <id>` 命令（双端）——教训可删即恢复。**治理可见性**：状态卡行尾显示行 id；MCP `kind` 扩展 `goal/decision/feedback` 直查结构化表 —— **已落地**
   - 压力导航：状态卡检测上下文压力，超阈值附压缩建议 —— 规划
   - 交接卡：Stop 时拼"会话交接卡"，新会话开场读取 —— 规划
6. **场景级保真回归集**：跨压缩保真场景入回归（decision-chain / repeat-question / goal-retention / file-lineage / compact-fidelity / injection-follow / scope-filter / migration-lossless / rebuild-recovery / isolation），`pnpm eval` 入 CI 门禁 —— **已落地（10 场景）**
7. **dsh 适配器**：MCP overlay 零代码挂载 + 原生插件三接缝（`session/event` 订阅 / `agent.inject()` 注入 / `ctx.tools` 注册）+ 多写者并发写验证 —— **已完成**

验收：功能正确性在底座无关层验收；注入效果（状态卡遵循率）在 dsh 上验收。

## 1. 产品包络

**定位**：跨底座会话保真层——确定性无损捕获 + 跨压缩边界保真 + 决策/目标状态机 + 场景级验证体系；知识记忆集成第三方 provider。

**顶层设计原则**：**主动权在 Thread，不把希望放在模型上**——模型不可控，Thread 与模型的交互口越少越好；状态卡主动注入提醒驱动查询，模型只需记住一条行为契约：**"需要啥就来问，别自己瞎猜"**。

**分层架构**：适配器矩阵（接驳层：dsh 原生插件=旗舰；Claude·Codex=MCP+hooks；Qoder=hooks）→ 保真核心（底座无关：事件流水=无损写时建索引 → 结构化表=目标/决策状态机+反馈表+血缘 → BM25 检索=带引用回拉 → 状态卡注入=O(1) 分层优先级）→ 集成层（provider 抽象：知识记忆=成熟 provider 集成；压缩=底座 compaction checkpoint 订阅；语义检索=可选 embedding，BM25 确定性兜底）。

**集成层边界**：集成层**只是增强和补足，不是强依赖**——Thread 核心不 import、不等待、不阻塞于任何第三方集成。**发布物只含"集成推荐清单"（文档级），不集成打包**。MVP 默认本地 BM25 兜底（core 自带），provider 缺失时功能降级而非报错。

**功能边界（做 9 / 不做 4）**：做 ① 确定性无损捕获 ② 跨压缩 checkpoint + 状态卡回归 + 引用回拉 ③ 决策/目标状态机 ④ 场景级验证体系（回归集+度量+eval 工具链）⑤ 状态卡注入（预算约束）⑥ 跨会话继承（会话内>项目>用户>全局）⑦ 一体化治理（superseded/冲突裁决/审计溯源）⑧ 确定性交接卡 ⑨ 存储治理（源头控制）。不做：压缩本身 / 知识图谱·代码图谱自建 / LLM 蒸馏 / 语义检索自建。

**存储治理**：
- 源头控制（写时即控）：① **大正文 spill**——事件只存元数据+摘要+引用，大块原文 spill 文件或直接引用底座日志（dsh 订阅原生日志**零正文复制**）；② **索引分层**——FTS5 只索引轻量文本，工具结果大块不建全文索引，检索按引用回拉原文；③ 项目分库天然隔离。
- 冷热归档（延后）：度量后用实测膨胀率定阈值，再设计冷分区。MVP 单项目体积可管理，不预建。
- 无损语义："无损"= 细节可检索回拉，非全文复制两份；原文留底座日志，Thread 存索引影子 + 引用。

## 2. 会话临时隔离（已落地）

同项目双代理并行做不相关工作时的状态卡互相干扰问题 → 会话级可变隔离开关。语义：对话上下文（消息/决策/反馈）**全链路仅自己可见**（合并视图 / search / queryEvents / expand / 血缘全部过滤）；项目事实（tool 事件）**共享不断链**（"谁在什么时间干了什么"可溯源，代价是事实的对话溯源丢失——已接受）；解除后历史仍隔离、后续共享、按需沉淀（`/thread-publish` 或自然语言指定转共享）。

触发 = 自然语言（"隔离/静默/别打扰" ↔ "解除隔离/恢复共享"）+ 显式命令（`/isolate` `/unisolate`），双通道不强制。**判定规则**：整条消息 trim 后精确匹配白名单（讨论性语句不触发）——隔离：`/isolate`、`隔离`、`开始隔离`、`进入隔离`、`临时隔离`、`静默`、`免打扰`、`别打扰`；解除：`/unisolate`、`解除隔离`、`退出隔离`、`恢复共享`；沉淀：`/thread-publish <kind> <id>`。

状态卡隔离模式标注"本会话已隔离"且只列本会话内容。schema：isolation 列 + session_isolation 表；dsh-thread 与 Qoder hooks 双端接入；evals isolation 场景（门禁 10/10）。

## 4. 作用域与命名空间

> 状态：设计已确认，已实现（结构化查询路径与合并视图落地）。动机：按项目隔离不应"全部隔离"——项目相关记忆（任务决策、事件）要隔离防污染，用户偏好与项目无关，应全局共享。

- **双作用域**：`global`（用户级，跨项目）与 `project`（项目级）。
- **启用范围**：反馈/偏好表启用双作用域；目标/决策默认 project，表内预留 `scope` 字段；事件流水按项目隔离，正文绝不进全局库（防污染）。
- **默认分类**：反馈**默认 global**（污染方向更安全）；确定性规则预过滤——项目限定词 → project，全局声明 → global；用户显式声明常缺失 → 由本地小模型分类兜底（确定性规则只做预过滤）。
- **显式选择**：只走对话内自然语言，不引入面板/命令。
- **存储模型**：结构化表进用户级单库 `~/.thread/structured.db`（行级 `project` 字段 + 反馈 `scope` 字段）；事件流水进 `~/.thread/projects/<规范化项目键>/events.db`——项目目录零污染。**项目身份键** = 规范化 git 根（realpath + 分隔符/大小写归一；非 git 退化为规范化 cwd）。
- **检索与注入**：查询合并"当前项目（project+global）+ 全局"行，按分数混排；非当前项目的 project 行硬性过滤。状态卡反馈区 = 项目内 + 全局（标注「全局」）；目标/决策区只显示当前项目。
- **状态卡限额**：总预算按注入位置分档（dsh 系统侧 ≤200 行 / Qoder 用户侧 ≤100 行）、分层 60/25/15、默认每区 3~5 条；正式调优由线上度量驱动。
- **冲突**：① 分层覆盖——项目级覆盖全局级，覆盖关系**并列展示 + 标注作用域**，不静默；② 同层多写者冲突——**先到先得 + 后来者选择**：状态卡提醒 → 用户当前会话表态跟随或 session 级覆盖，project 级仅建立者可改。
- **反馈生命周期**（撤销/覆盖）：MVP 靠冲突展示兜底（改口的两条偏好都显示且带时间戳）。
